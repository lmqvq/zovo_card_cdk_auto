## 二、逐版本详细说明

**影响范围**

**验证**
- `go test ./internal/pro20x/...` 全过。

### v1.4.35.12 — 套餐映射与兑换单表

**改了什么**
- 新增 `plan.go`：CDK 套餐 → Pro20x planId 映射（plus / pro_5x / pro_20x / promax / credits）

**影响范围**

**数据变更**

- 不修改、不删除任何已有表和数据。

### v1.4.35.13 — 自建卡密生成器

**改了什么**
- 码表新增列：`source` / `expires_at` / `batch_no` / `agent_id` / `price_minor` / `bound_email`
- 生成 `ZC-` 前缀卡密（后续版本改为 `LD-`）
- 后台接口：`POST /admin/cdk/local/generate`、`GET /admin/cdk/local/list`

**影响范围**

- 卡台码的查询、兑换、对账全部照旧。

**数据变更**
- **只加列，不删列**。老数据 `source` 自动填 `'zovo'`。
- 迁移用 `pragma_table_info` 检查列是否存在，**幂等**，重复启动不会报错。

### v1.4.35.14 — 兑换分流到 Pro20x

### v1.4.35.16 — 防二次兑换 + CDK 页隔离

**改了什么**
- 兑换引入原子状态机（`unused → consuming → consumed`，失败回滚）
- 会话状态锁（`preflight → redeeming → running`）
- CDK 卡密页只查 `source='zovo'`，自建码不再混入

**影响范围**
- **CDK 卡密页的条数会减少**：从 501 条变成 500 条（少的那条是自建码，它移到了「自建卡密」页）。
- 卡台码的禁用/启用/复制/导出全部正常。

**数据变更**
- 无结构变更。

**验证**
- 双击兑换：第二次返回 409「兑换正在处理中」。
- 两标签页同时兑换：只有一个成功。

### v1.4.35.17 — 码长 24 位 + 预览限速 + 启动清理

**改了什么**
- 自建码随机长度从 12 位加到 20 位（总长 24 字符）
- 预览接口加同 IP 每分钟 30 次限速

**影响范围**
- **预览接口对 zovo 码也限速**：正常用户点预览不会触发（30 次/分钟足够）。
- 旧 12 位自建码仍可正常兑换。

## 三、数据安全声明

### 本次更新对数据库做了什么

| 操作 | 对象 | 说明 |
|---|---|---|
| 新增表 | `pro20x_orders` | 空表，自建码兑换单 |
| 新增列 | `cardplatform_cdk_codes.source` | 默认 `'zovo'`，老数据不受影响 |
| 新增列 | `cardplatform_cdk_codes.expires_at` | 默认 NULL |
| 新增列 | `cardplatform_cdk_codes.batch_no` | 默认空串 |
| 新增列 | `cardplatform_cdk_codes.agent_id` | 默认空串 |
| 新增列 | `cardplatform_cdk_codes.price_minor` | 默认 0 |
| 新增列 | `cardplatform_cdk_codes.bound_email` | 默认空串 |
| 新增列 | `cardplatform_cdk_codes.note` | 默认空串 |
| 新增配置 | `site_settings.pro20x_*` | 5 个配置项 |

### 明确没有做的事情

- ❌ 没有 `DROP TABLE`
- ❌ 没有 `DROP COLUMN`
- ❌ 没有 `DELETE` 任何业务数据
- ❌ 没有修改已有列的类型或默认值
- ❌ 没有重置任何卡密状态

### 迁移的安全性

所有 `ALTER TABLE ADD COLUMN` 都先用 `pragma_table_info` 检查列是否存在：

```go
var n int
DB.QueryRow(`SELECT COUNT(*) FROM pragma_table_info('cardplatform_cdk_codes') WHERE name = ?`, col).Scan(&n)
if n > 0 { continue }   // 已存在，跳过
DB.Exec(ddl)
```

**重复启动、重复升级都不会报错，也不会丢数据。**

### 唯一会「变动」的数据

```sql
-- 服务启动时：把上次进程中断留下的中间态放回可用
UPDATE cardplatform_cdk_codes SET status='unused'
WHERE source='local' AND status='consuming';
```

这条只影响**自建码**，且只在服务重启时执行一次。卡台码（`source='zovo'`）完全不在范围内。

## 四、回滚方案

### 回滚到 v1.4.35.10

```bash
cd /opt/spacex_card_cdk_auto
systemctl stop cdk-recharge
cp cdk-recharge cdk-recharge.bak.$(date +%s)     # 先备份当前二进制
# 下载 v1.4.35.10 的 Release 包，替换二进制
systemctl start cdk-recharge
```

**回滚后会发生什么**

- 新表 `pro20x_orders` 留在库里（老版本不读它，无害）
- 码表多出的 7 个列留在库里（老版本不读，无害）
- `site_settings` 里的 `pro20x_*` 配置留在库里（老版本不读）
- 自建码在 CDK 页会重新显示（老版本没有 `source` 过滤）

**结论：回滚不需要任何数据库操作，也不会丢数据。**

### 回滚前建议备份

```bash
sqlite3 /opt/spacex_card_cdk_auto/data/cdk_recharge.db ".backup /root/backup_$(date +%Y%m%d_%H%M).db"
```
